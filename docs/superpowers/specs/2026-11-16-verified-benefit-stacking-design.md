# 확인된 중복 혜택 합산

사용자 승인: 기존 규칙은 유지하고 중복 가능하다고 확인된 혜택만 명시해서 합산한다.

## 범위와 접근

- 전체 규칙 합산은 중복 불가·이미 합산된 요율을 과대 계산하므로 사용하지 않는다.
- 현행 최대 한 규칙만 유지하는 방식은 확인된 기본+추가 적립을 표현하지 못한다.
- 선택한 방식: `benefit_rules.stackable`을 명시적으로 켠 규칙끼리만 합산한다. 기본값은 false이며 기존 시드에는 표시를 추가하지 않는다. 표시 문구나 한도 그룹 차이로 합산을 추론하지 않는다.
- 미표시 규칙은 각각 단일 후보이고 표시된 규칙은 한 합산 후보를 만든다. 두 방식 중 최종 혜택이 큰 결과를 사용하며 동률이면 가정이 적은 후보, 적용 규칙 수가 적은 후보, 규칙 ID 순으로 결정한다. 기존 규칙 사이의 동률은 유지된다.
- 필터(검증·유효기간·대상·조건·실적)와 미달·미확인 정책은 유지한다. 합산 후보도 필터를 통과한 규칙만 사용한다.

## 계산·한도·출처

- 규칙별 절사와 한도를 적용한 개별 후보 금액 내림차순, 동률 ID 오름차순으로 합산 후보를 배분한다. 이미 배분된 금액은 공유 하위/상위 한도의 잔여에서 뺀다. 금액 한도 트리는 기존 단일 parent 구조를 사용한다.
- 양수 혜택만 적용 목록에 담는다. 공유 한도의 금액 차감은 해당 한도에 연결된 실제 혜택 금액만 합산하며, 횟수는 거래당 한 번만 차감한다.
- 모르는 잔여는 기간 전체 한도로 가정하고 ASSUMED를 유지한다. 상태를 저장하거나 확정으로 바꾸지 않는다.
- 카드 필요 실적은 적용된 규칙들의 최대 필요 실적이다. 가정·출처는 실제 양수 혜택에 쓰인 규칙만 합친다.

## 응답과 기록

- 내부 계산 결과에 규칙 ID·개별 최종 금액 목록을 추가한다. 기존 단일 규칙 접근자·생성자는 유지한다.
- appliedRules의 합계가 expectedBenefit과 같아야 한다. 계산식은 규칙별로 반환한다.
- remainingLimitsAfter는 한도 ID별 합산 차감과 거래당 횟수를 한 번씩 반환한다. 무제한 그룹도 연결 정보에는 유지한다.
- 기존 카드 단위 calculation은 대표 혜택(최종 금액 내림차순, ID 오름차순)의 계산식으로 유지한다. remainingLimitAfter는 대표 혜택에 연결된 금액 한도의 합산 후 최저 잔여다. 복수 혜택 합계를 단일 비율 계산식으로 표현하지 않는다.
- 질문은 적용 규칙들의 실제 가정 대상을 합쳐 중복 제거한다. affectsRank·확인된 정보 추천은 같은 확장 엔진으로 다시 계산한다.
- 새 추천의 상세를 저장하고 GET·결제 확인은 그 스냅샷만 사용한다. 과거 추천은 재계산하지 않는다. 기존 결제 원장이 한도별 projection으로 차감·복원하도록 유지한다.

## 비범위

실제 상품 stackable 역채움(카드 데이터 담당자 검증 필요), 동률 연회비 정책 변경, 채널·결제수단 정책 변경, 저장 전 미리보기, 배포·main 머지.

## 검증

기존 규칙 결과 유지, 표시/미표시 혼합 금지, 합산과 단일 최대 비교, 공유 금액/횟수·상위 한도, 0원·미확인·절사·안정 순서, 가정 순위 변화, 실제 HTTP 생성/조회/확인/취소·복원·직접 입력 보호·과거 스냅샷 유지.
